RepoAvatar — Component Demo

Visual regression tests and integration demos for the RetinaX RepoAvatar standalone UI component.

✓ Test 1 — HTML data-* Attribute Auto-Init

Auto-initialised via data-* attributes

The component reads configuration from data-* attributes on a .repo-avatar-mount element and initialises automatically on DOMContentLoaded. No JS required beyond loading repo-avatar.js.

ℹ Test 2 — Programmatic Constructor API

Instantiated via new RepoAvatar(el, opts)

Full programmatic control: construct with a plain <div>, pass config as a JS object. Stars / forks formatted with K suffix. Custom org logo, custom network name, custom max contributors.

ℹ Test 3 — .update() Live Re-render

Dynamic update after initial render

Call instance.update({ stars: 999 }) to merge new data and re-render without recreating the component. Use the buttons below to test.

⏳ Test 4 — Loading Skeleton State

Skeleton while fetching live data

Call instance.showLoading() before a network request, then instance.update(data) when the response arrives. The button simulates a 1.5 s fetch delay.

⚠ Test 5 — Error State

Error state when data cannot be loaded

Trigger instance.showError('GitHub API rate limit exceeded.') to display a graceful error UI with no broken card body.

✓ Test 6 — Number Formatting (k / M)

Stars 14,200 → "14.2k", forks 1,000,000 → "1M"

Large star and fork counts are formatted with K/M suffixes for compact display. The component also correctly handles zero values and non-numeric inputs.

✓ Test 7 — Contributor Overflow (+N badge)

9 contributors, max 5 visible → "+4" overflow badge

When there are more contributors than maxContributors (default 5), a +N overflow badge is appended after the visible avatar stack.
